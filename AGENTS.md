# AGENTS.md

`@scinorandex/sparse` — LR(1) parser generator library (TypeScript, CJS via tsc, yarn 1).
Single package: `src/` = library + CLI, `example/` = runnable demos, `test/` = vitest suite.
README.md is the user-facing doc (grammar syntax, reducer contract, recovery guide, API reference).

## Commands
- Typecheck: `yarn tc` (covers src/, example/ and test/)
- Build: `yarn build` → `dist/` (CLI is `dist/cli.js`)
- Test: `yarn test` (vitest; builds `dist/` first because `test/cli.test.ts` runs the CLI)
- Run examples: `tsx example/<name>/example.ts` — tsx is global, not a repo dep; `node file.ts` fails (enums)
- Table CLI: `node dist/cli.js --input=<grammar> --output=<table>` (build first); output matches committed tables exactly
- `yarn bench` exists but there are no bench files. Verify with `yarn tc && yarn test` plus the examples.
- `dist/` and `yarn.lock` are gitignored.

## Self-hosting / codegen (critical, easy to break)
- The lib parses its own grammar-file and table-file formats using **pre-generated** LR(1) states:
  `src/meta/states.ts` (grammar format) and `src/table/states.ts` (table format) are generated files —
  byte-identical copies of `example/selfhosted/codegen-meta.ts` and `codegen-table.ts`.
- To change the grammar/table file syntax: edit `example/selfhosted/01-meta-grammar.txt` and/or
  `02-table-grammar.txt`, run `tsx example/selfhosted/example.ts`, then copy the regenerated
  `codegen-*.ts` over the two `src/.../states.ts` files. The old (checked-in) parser must still
  parse the modified grammar (bootstrap constraint).
- `test/codegen.test.ts` enforces this: it regenerates both state files in memory and compares them to
  the checked-in ones. It compares objects (not file bytes) so the `cp` step stays manual.
- Changing the *lexer* rules in `grammarLexerGenerator` (e.g. allowing `-` inside identifiers) does NOT
  change the generated states — the token types and positions stay the same.

## Non-obvious behavior
- `?`, `*`, `+` groups and `|` alternatives are unrolled into extra productions; `*`/`+`
  create `autogen-N` productions whose reducer is named `autogenerated-kleene` — user reducers must
  handle it (see `example/kleene-test/`). `?` on a group that can match nothing produces an empty
  production and is rejected by `validateProductions`.
- Modifiers only apply to parenthesized groups: `([A] [B])?`, not `[A]?`.
- `|` alternatives live inside a single token: `[A | B]`, `<A | B>`.
- Two construction paths: `Sparse.fromProductions(...)` builds states at runtime (slow, ~30s for
  150 productions) vs `Sparse.fromGrammarFile(...)` / `new Sparse({ productions, states })` (fast).
- Reducers are keyed by production name (`<LHS: name>` in the grammar file); nameless productions
  have `name: null`. Production index 0 is the accept production —
  the parse loop breaks on it without calling the reducer. `oldInput.index` is the pre-unrolling index.
- Table file format: one line per state, comma-separated `[TERMINAL]=sN|rN` and `<VARIABLE>=M`.
  The reader preserves file order via `getItemsReversed()` (the item lists are built right-recursively).
- Errors flow as `Result<T>` (`{ success: false, reason, token }`); `buildProductions` /
  `Sparse.fromProductions` / `buildStates` are the throwing wrappers.
- `GeneratorResult.ActionTable` is sparse: a state whose items only move to other states has no entry.
  `toStates()`/`toTable()` use `Array.from`, not `map`, so state numbering stays aligned; `toTable()`
  throws for such grammars because the file format cannot express an action-less state.
- LALR(1) mode merges same-core LR(1) states. Same-core states always agree on their shifts, gotos and
  reduce targets, so the conflict branch in `mergeStatesForLALR` is currently unreachable.

## Key files
- `src/generator.ts` — LR(1) state construction (first/follow sets, item-set expansion), `toTable()` serialization
- `src/parser.ts` — runtime parser loop + `recover` error-recovery callback API (`insertToken`, `finish`, `crash`)
- `src/meta/selfhosted.ts` — grammar-file parser + production unrolling
- `src/meta/common.ts` — `Production` type + `validateProductions`
- `src/table/selfhosted.ts` — table-file parser (`tryBuildStates`), `src/table/validate.ts` — table validation
- `src/cli.ts` — `--input/--output/--lalr/--check/--stdout/--help`
- `example/` — `math` (prebuilt table), `kleene-test` (`*`/`+`), `LoLang` (large grammar + recovery, exports
  its lexer for the tests), `selfhosted` (codegen)
- `test/` — `grammar`, `table`, `parser`, `lalr`, `codegen`, `cli`
